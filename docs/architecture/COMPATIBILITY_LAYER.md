# Архитектура слоя совместимости Aeronautics Plus

Статус: действующий архитектурный контракт.  
Целевая платформа: Minecraft 1.21.1, NeoForge, Java 21.  
Первая проверяемая интеграция: TerraFirmaCraft 4.2.11.

## 1. Роль двух собственных модов

Большой научный мод остаётся фундаментом сборки. Он задаёт авторитетные материалы,
физико-химические процессы, машины и прогрессию и по возможности заменяет разрозненные
варианты одной и той же системы собственным согласованным функционалом. Поэтому его
архитектура не должна зависеть от наличия каждого стороннего мода.

**Aeronautics Plus — слой совместимости механики и физики аппаратов.** Он использует
возможности Create Aeronautics, Sable и других модов, согласует их физические интерфейсы,
добавляет недостающие переходники и развивает аппараты, которые нельзя получить простой
заменой рецептов. К этой области относятся тяга, вращение, валы, роторы, аэродинамические
поверхности, плавучесть, движители и совместная работа физических конструкций.

Это разделение не запрещает интеграцию большого мода. Напротив, Aeronautics Plus должен
принимать его материалы и параметры как авторитетные входы, но не копировать его
химию, металлургию, энергетику или полную прогрессию.

## 2. Границы ответственности

| Область | Авторитетный владелец | Роль Aeronautics Plus |
|---|---|---|
| Химия, материалы, металлургия, энергетика | большой научный мод | потребитель тегов, свойств и API |
| Общая прогрессия сборки | большой научный мод + ограниченный KubeJS | рецепты и узлы аппаратов без параллельной технологической ветки |
| Тяга, вращение, передача момента | Aeronautics Plus + API Create Aeronautics/Sable | реализация и согласование |
| Несущие, рулевые и соосные роторы | Aeronautics Plus | реализация компонентов и физики |
| Сторонние двигатели и движители | исходный мод | крепления, переходники и физическая совместимость |
| Геология, климат и Overworld | TerraFirmaCraft при его наличии | только чтение данных, влияющих на физику; worldgen не переопределять |
| Склоны и микрогеометрия поверхности | исходный terrain-мод + compat-модуль | мост к физическим блокам и материалам TFC без второго worldgen |
| Временные pack-specific правки | KubeJS | прототипирование; стабильную механику переносить в Java/data layer |

## 3. Жёсткие правила модульности

1. Ни один необязательный мод не становится обязательной зависимостью ядра только ради
   одного рецепта или адаптера.
2. Наличие мода сначала проверяется через `ModList`; классы его API разрешено загружать
   только внутри соответствующего compat-модуля.
3. Простые материальные соответствия реализуются через общие теги `c:*` и стабильные
   теги `aeronauticsplus:*`, а не через списки предметов в Java.
4. Рецепт Aeronautics Plus обращается к собственному семантическому тегу. Datapack
   интеграции может расширить этот тег без замены самого рецепта.
5. Прямой API нужен только там, где тегами и рецептами нельзя выразить физическое
   поведение.
6. Интеграция не имеет права запускать второй Overworld worldgen, второй календарь или
   вторую систему сезонов поверх TerraFirmaCraft.
7. Каждая связка проверяется минимум в четырёх конфигурациях: без optional-мода, только с
   ним и обязательными зависимостями, в целевой сборке и на dedicated server.
8. Старый основной мир не используется для тестов перехода на TFC; нужен новый
   `tfc:overworld` в клоне профиля.

## 4. Первый слой: материалы лопастей

Рецепты винтов больше не должны напрямую владеть внешними material tags. Введены теги:

- `aeronauticsplus:blade_materials/wood` → `#minecraft:planks`;
- `aeronauticsplus:blade_materials/iron` → `#c:ingots/iron`;
- `aeronauticsplus:blade_materials/aluminum` → `#c:ingots/aluminum`;
- `aeronauticsplus:blade_materials/steel` → `#c:ingots/steel`.

Аудит исходных data-файлов TerraFirmaCraft 4.2.11 подтвердил:

- все TFC-доски входят в `minecraft:planks`;
- `tfc:metal/ingot/steel` входит в `c:ingots/steel`;
- TFC также предоставляет `c:ingots/wrought_iron`, `c:sheets/steel` и
  `c:sheets/wrought_iron` для следующего этапа рецептов.

Поэтому деревянные и стальные винты уже получают базовую совместимость без прямого
импорта классов TFC. Алюминий TFC не добавляет; алюминиевая ветка остаётся материалом
большого научного или другого технологического мода.

Текущий мост намеренно не объявляет баланс завершённым: обычный shaped-рецепт из слитков
будет заменён или дополнен TFC-осмысленной цепочкой листов, ковки и соединений только
после проверки реальных recipe serializers и прогрессии в тестовом профиле.

## 5. Поэтапный план TerraFirmaCraft

### C1 — минимальный материальный слой

- [x] необязательная metadata-зависимость `tfc`;
- [x] безопасное runtime-обнаружение без импорта TFC API;
- [x] собственные расширяемые теги материалов лопастей;
- [x] рецепты винтов переведены на эти теги;
- [x] validator проверяет границу тегов и optional-модуль.

### C2 — изолированный запуск

- [ ] собрать клон профиля с TFC 4.2.11 и Patchouli;
- [ ] оставить Create, Create Aeronautics, Sable и Aeronautics Plus;
- [ ] создать новый `tfc:overworld`;
- [ ] проверить client и dedicated server, datapack reload, EMI/JEI и все рецепты;
- [ ] убедиться, что отсутствие TFC не меняет поведение текущего профиля.

### C3 — согласованная производственная цепочка

- [ ] сопоставить TFC ingot/sheet/double sheet/rod с материалами большого мода;
- [ ] исключить рецепты, обходящие ковку, сварку и обработку металла;
- [ ] добавить conditional recipes только после проверки формата TFC 4.2.11;
- [ ] сохранить fallback для сборок без TFC;
- [ ] проверить рецепты, теги, advancements и отображение EMI/JEI.

### C4 — физика среды и аппаратов

- [ ] определить стабильные API TFC для высоты, температуры, осадков и климата;
- [ ] отделить реальные входные величины от декоративных биомных названий;
- [ ] вводить влияние среды на тягу/подъёмную силу только с конфигом и тестами;
- [ ] не дублировать календарь, сезоны, снег и сельскохозяйственную модель TFC;
- [ ] сначала завершить и не ломать RPM-зависимую тягу и точную ось винтов.

### C5 — остальные связки

1. Create / Create Aeronautics / Sable;
2. Terrain Slabs и материалы поверхности TFC;
3. AgriCraft и Productive Bees после удаления optional-контента BOP;
4. двигатели, подводные аппараты и прочие физические моды по отдельной матрице;
5. полный регрессионный запуск целевой сборки.

Добавление JAR в папку `mods` само по себе не считается завершённой совместимостью.
Для каждой строки нужны владелец данных, механизм адаптации, режим отказа и проверяемая
приёмка.

## 6. Удалённый природный слой

После перехода на TFC следующие моды не входят в целевую архитектуру:

- Biomes O’ Plenty;
- TerraBlender, если dependency-аудит не найдёт другого потребителя;
- Serene Seasons Plus;
- GlitchCore, если после удаления перечисленных модов нет другого обязательного dependent.

Aeronautics Plus не должен добавлять для них новые runtime hooks. Старые строки
локализации могут оставаться до следующей полной пересборки RU-pack, но не считаются
активной функциональной зависимостью.
